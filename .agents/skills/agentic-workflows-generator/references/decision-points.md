# 判断確認ポイント一覧（ユーザーに確認・選択させる箇所）

ワークフロー生成・更新・セットアップの中で、**正解が利用形態（会社/個人など）や好みで変わる箇所**の一覧です。ここに該当したら、推測せず**選択肢を提示して質問**し、ユーザーの判断を仰いでください。各項目に推奨デフォルトを示します。

---

## 🔑 1. Copilot の認証方式（会社/組織 か 個人 か）← 最重要

**いつ聞くか**: Copilot エンジンを使うワークフローを作る/動かすとき、認証・シークレットの話になったとき。

| 選択肢 | こういう人向け | 内容 |
|--------|--------------|------|
| **A. `copilot-requests: write`（推奨・組織/複数人）** | 会社・チーム・組織リポジトリ | ワークフローに権限を付けるだけ。**シークレット不要**。課金は組織の一元課金。個人トークンを共有しない |
| **B. `COPILOT_GITHUB_TOKEN`（個人）** | 自分専用の個人リポジトリ | Copilot 権限を持つトークンをシークレット登録。自分しか触らない前提 |

**質問例**: 「このワークフローは**会社（組織）**で使いますか、それとも**個人**で使いますか？ 組織なら `copilot-requests: write`（シークレット不要・推奨）、個人なら `COPILOT_GITHUB_TOKEN` を使います。」

> ⚠️ **複数人開発で個人トークンを共有シークレットに入れない**（なりすまし・課金付け替え・退職時の停止の原因）。共有なら A、または Bot/GitHub App のトークンを使う。詳細は [auth-and-secrets.md](auth-and-secrets.md) / docs の [model-policy.md](../../../docs/references/model-policy.md)。

## 🤖 2. 使用モデルの選択

**いつ聞くか**: モデルを固定するか、手動ディスパッチで選ばせるか決めるとき。

| 観点 | 確認すること |
|------|-------------|
| 固定 or 選択 | 1モデル固定か、`workflow_dispatch` の `choice` で実行時に選ばせるか |
| どのモデル | 採用4種（`claude-sonnet-4.6` / `gpt-5.4` / `gpt-5.3-codex` / `claude-haiku-4.5`）のどれを既定にするか |

**推奨デフォルト**: 通常 `claude-sonnet-4.6`、コード調査系は `gpt-5.3-codex`、定型・大量は `claude-haiku-4.5`。迷う場合は用途を聞いて提案。詳細は [model-policy.md](model-policy.md)。

## ⏰ 3. トリガー（自動 or 手動）と自動実行の是非

**いつ聞くか**: トリガーを決めるとき。特に `schedule`（cron）を入れるとき。

| 確認すること | 理由 |
|-------------|------|
| 自動（push/issues/schedule）か手動（workflow_dispatch）か | 自動は「放置で勝手に動く」。コスト・ノイズに直結 |
| schedule の場合の頻度・時間帯 | 走るたびに AI 課金が発生 |
| まず手動で試すか | `workflow_dispatch` を併設すれば schedule を待たず検証できる |

> ⚠️ `schedule` は**デフォルトブランチに push されて初めて有効**になり、その後は放置で動く。「今は動かしたくない」場合は push しない / ワークフローを Disable する選択肢を提示する。

## ✍️ 4. 書き込み（safe-outputs）の範囲

**いつ聞くか**: AI に何を「書かせる」か決めるとき。

| 確認すること | 例 |
|-------------|-----|
| どこに出力するか | コメント / Issue / PR / ラベル |
| 直接変更 or 提案 | コードや README は**直接 push せず PR 提案**が安全（既定推奨） |
| 上限 | `max:` をいくつにするか（暴走防止） |

**推奨デフォルト**: 変更系は `create-pull-request`（人間レビューを挟む）。コメント・ラベルは `max` を小さく。

---

## 🔁 5. 状態の持ち方（カウント・前回引き継ぎが要るか）

**いつ聞くか**: 「N回まで」「前回の続き」など実行間の記憶が要りそうなとき。

| 確認すること | 対応 |
|-------------|------|
| 回数や前回結果を覚える必要があるか | ラベル（回数）/ 過去コメント（前回結果）/ Issue（構造化）で永続化 |
| リセット手段は要るか | ラベルを外せば初回に戻す等 |

詳細は [state-persistence-patterns.md](state-persistence-patterns.md)。

## 📦 6. 配置・移植まわり

**いつ聞くか**: 別リポジトリへコピーする、`gh aw init` を走らせるとき。

| 確認すること | 注意 |
|-------------|------|
| `gh aw init` の実行 | 既存の `agentic-workflows-generator` スキル等を**上書きしうる**。事前バックアップ・差分確認を提案 |
| 別リポジトリへ移植 | `.md` を持っていき、移植先で `gh aw compile` し直すのが正解（`.lock.yml` は環境依存） |
| コミット | `.md` と `.lock.yml`（＋自動生成 `agentics-maintenance.yml`）を両方コミット。push 前にブランチ確認 |

## 質問の出し方（テンプレート）

```
{分岐点の説明}。次のどちらにしますか？

- A: {選択肢A}（{推奨なら「推奨」}） — {向いている人/理由}
- B: {選択肢B} — {向いている人/理由}

{利用形態を聞く必要があれば}: これは会社（組織）で使いますか、個人で使いますか？
```

確認できたら選択に従って続行し、同一セッションでは同じことを繰り返し聞かない。
