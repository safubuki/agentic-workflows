# 02. セットアップ

## 前提条件

| 必要なもの | 確認コマンド | なぜ必要か |
|-----------|-------------|-----------|
| GitHub CLI（`gh`） | `gh --version` | `gh aw` は gh の**拡張**として動くため、本体が前提 |
| GitHub 認証 | `gh auth status` | 拡張の取得・ワークフロー実行・シークレット設定に GitHub への認証が必要 |
| 対象リポジトリへの push 権限 | — | `.md` / `.lock.yml` をコミットするため |
| 使う AI エンジンの API キー | 後述 | AI エンジン（Claude 等）を呼ぶため |

> 💡 全体の依存関係: **gh 本体 → 認証 → gh aw 拡張 → コンパイル/実行**。上から順に揃えます。

## Step 0: GitHub CLI（gh）本体のインストール

`gh aw` は gh の拡張なので、まず gh 本体が必要です。未導入なら入れます。

```powershell
# Windows（winget）
winget install --id GitHub.cli --source winget --accept-package-agreements --accept-source-agreements
```

```bash
# macOS（Homebrew）
brew install gh
```

> ℹ️ **インストール直後は PATH が現在のターミナルに反映されていない**ことがあります。`gh` が「コマンドが見つからない」と出たら、**ターミナルを開き直す**か、フルパス（Windows 既定: `C:\Program Files\GitHub CLI\gh.exe`）で実行してください。

確認:

```bash
gh --version
```

## Step 1: GitHub 認証（gh auth login）

拡張のインストールやワークフロー実行には GitHub への認証が必要です。

```bash
gh auth login
```

対話プロンプトの基本的な選び方:

1. **GitHub.com** を選ぶ
2. プロトコルは **HTTPS**（推奨）
3. 認証方法を選ぶ — **ブラウザ方式**か **PAT（トークン）方式**。この2つの**違いと使い分け**は次を参照:

📄 **[references/gh-auth-guide.md](references/gh-auth-guide.md)**

確認:

```bash
gh auth status
```

> ✅ `Logged in to github.com account <あなた> ` と表示され、`Token scopes` に **`repo`** と **`workflow`** が含まれていれば OK です。`workflow` スコープが無いと、Actions ワークフローファイルの push が拒否されることがあります。

## Step 2: gh aw 拡張のインストール

> ⚠️ このステップは **Step 1 の認証が完了してから**実行します（拡張の取得に認証が要るため）。

```bash
gh extension install github/gh-aw
```

インストール確認:

```bash
gh aw version    # 例: gh aw version v0.80.9
gh aw --help
```

更新する場合:

```bash
gh extension upgrade gh-aw
```

## Step 3: オーサリング環境の初期化（推奨）

```bash
gh aw init
```

`gh aw init` は次を行います（**オーサリング体験を有効化するために必須**）:

- `.github/skills/agentic-workflows/SKILL.md`（ディスパッチャースキル）を作成
- MCP サーバー連携をセットアップ
- VS Code 設定を構成

> ⚠️ **既存スキルの上書き注意**: 本リポジトリには既に `.github/skills/agentic-workflows/SKILL.md`（手動作成版）があります。`gh aw init` がこれを上書きする可能性があるため、実行前にバックアップを取り、実行後に `git diff` で差分を確認して取捨選択してください。

## Step 4: AI エンジンのシークレット設定

使うエンジンに応じてリポジトリシークレットを登録します。

| エンジン | `engine:` 値 | 必要なシークレット | 備考 |
|---------|-------------|------------------|------|
| Claude（Anthropic）**推奨** | `claude` | `ANTHROPIC_API_KEY` | キーレス（WIF）も可 |
| Copilot（既定） | `copilot` | `COPILOT_GITHUB_TOKEN` または `copilot-requests: write` 権限 | — |
| Codex（OpenAI） | `codex` | `OPENAI_API_KEY` | — |
| Gemini（Google） | `gemini` | `GEMINI_API_KEY` | — |

### Claude のシークレット登録例

```bash
gh secret set ANTHROPIC_API_KEY
# プロンプトに API キーを貼り付ける
```

> ℹ️ シークレットは**リポジトリの Settings > Secrets and variables > Actions** にも表示されます。組織で共有する場合は組織シークレットを使います。

> 💡 `gh secret set` も Step 1 の `gh auth` の認証情報を使って GitHub にシークレットを登録します。認証していないと失敗します。

## Step 5: 最初のワークフローを作成・コンパイル

`.github/workflows/hello.md` を作成:

```markdown
---
name: Hello Agentic
on:
  workflow_dispatch:
engine: claude
permissions:
  contents: read
safe-outputs:
  create-issue:
    max: 1
---

# あいさつ Issue を作る

このリポジトリの目的を1段落で説明する Issue を1件作成してください。
タイトルは「👋 Agentic Workflows 動作確認」とします。
```

コンパイル:

```bash
gh aw compile
```

`.github/workflows/hello.lock.yml` が生成されます。

## Step 6: コミットしてプッシュ

```bash
git add .github/workflows/hello.md .github/workflows/hello.lock.yml
git commit -m "Add hello agentic workflow"
git push
```

> ⚠️ **`.md` と `.lock.yml` は必ず両方コミット**してください。`.lock.yml` がないと Actions は実行されず、`.md` だけだと「コンパイル前」のままになります。
> なお、ワークフローファイルを push するには認証トークンに **`workflow` スコープ**が必要です（Step 1 参照）。

## Step 7: 実行

- **CLI から**: `gh aw run hello`
- **GitHub UI から**: リポジトリの **Actions** タブ → 該当ワークフロー → **Run workflow**

## チェックリスト

- [ ] `gh --version` が通る（gh 本体が導入済み）
- [ ] `gh auth status` で `repo` / `workflow` スコープ付きで認証済み
- [ ] `gh extension install github/gh-aw` が成功した（`gh aw version` が出る）
- [ ] `gh aw init` を実行した（既存スキルの差分を確認した）
- [ ] 使うエンジンのシークレットを登録した
- [ ] `.md` を書いて `gh aw compile` した
- [ ] `.md` と `.lock.yml` を両方コミットした

次は [03-ワークフローの書き方.md](03-ワークフローの書き方.md) でフロントマターの全項目を確認してください。
