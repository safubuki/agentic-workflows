# 03. ワークフローの書き方

ワークフローは `.github/workflows/<名前>.md` に置き、**フロントマター（YAML 設定）** と **本文（自然言語の指示）** の2部構成で書きます。

```markdown
---
# ここがフロントマター（YAML）
name: ...
on: ...
engine: ...
---

# ここから本文（自然言語の指示）
...
```

---

## フロントマター全項目早見表

| フィールド | 用途 | 例 |
|-----------|------|-----|
| `name` | 表示名 | `PR AI Review` |
| `description` | 説明 | `指定 PR を AI レビュー` |
| `on` | トリガー設定 | `workflow_dispatch` / `push` / `issues` / `schedule` |
| `permissions` | GitHub API の権限スコープ | `contents: read` |
| `engine` | AI プロバイダ（とモデル） | `claude` |
| `tools` | 利用可能な機能 | `github` / `web-search` / `playwright` |
| `safe-outputs` | 安全な書き込み出力 | `add-comment` / `create-pull-request` |
| `network` | ネットワークアクセス制御 | `defaults` / 許可ドメイン |
| `timeout_minutes` | 実行時間上限 | `20` |
| `roles` | 実行を許可する権限ロール | `[admin, maintainer, write]` |

---

## トリガー（`on`）

### 手動実行（workflow_dispatch）+ 入力パラメータ

本リポジトリの PR レビューワークフローで使う中心パターンです。

```yaml
on:
  workflow_dispatch:
    inputs:
      pr_number:
        description: "レビューする PR 番号"
        type: string
        required: true
      model:
        description: "レビューに使う AI モデル"
        type: choice
        options:
          - claude-sonnet-4.6
          - gpt-5.4
          - gpt-5.3-codex
          - claude-haiku-4.5
        required: true
        default: claude-sonnet-4.6
      max_reviews:
        description: "AI レビューの最大回数"
        type: choice
        options:
          - "1"
          - "2"
          - "3"
        default: "3"
        required: true
```

`type` には `string` / `choice` / `boolean` / `number` が使えます。
`choice` は **`options:` で選択肢を列挙**し、`default:` で既定値を指定します。

### その他のトリガー

```yaml
on:
  push:
    branches: [main]
    paths: ["src/**", "lib/**"]   # 特定パスの変更時のみ
  pull_request:
    types: [opened, synchronize]
  issues:
    types: [opened]
  schedule:
    - cron: "0 9 * * *"            # 毎日 9:00 UTC
```

## 本文での入力・コンテキストの参照

本文の中では **GitHub Actions の式（expression）** を使えます。ただし gh-aw では使える式が**許可リストで制限**されています（例: `github.sha` は不可）。下表のような代表的な式を使い、コンパイル時に `unauthorized expressions` と出たらメッセージの許可式に置き換えてください。

| 参照したいもの | 書き方 |
|---------------|--------|
| dispatch 入力 | `${{ github.event.inputs.pr_number }}` |
| PR 番号（PR トリガー時） | `${{ github.event.pull_request.number }}` |
| push の HEAD コミット | `${{ github.event.head_commit.id }}` |
| リポジトリ名 | `${{ github.repository }}` |
| 実行者 | `${{ github.actor }}` |
| イベント名 | `${{ github.event_name }}` |

> 💡 手動ディスパッチには PR コンテキストが自動で付かないため、**PR 番号は入力パラメータとして明示的に受け取り**、本文で `${{ github.event.inputs.pr_number }}` として参照します。

## 権限（`permissions`）

```yaml
permissions:
  contents: read
  pull-requests: read   # 書き込みは safe-outputs 経由なので read で十分なことが多い
  issues: read
```

> 🔑 **最小権限の原則**: AI 自体は読み取り専用に保ち、書き込みは `safe-outputs` に任せます。

## エンジン（`engine`）とモデル

> 🟢 本リポジトリの既定は `engine: copilot`。モデルは [references/model-policy.md](references/model-policy.md) の4種から選びます。

### 短縮形

```yaml
engine: copilot
```

### オブジェクト形（モデル・上限を指定）

```yaml
engine:
  id: copilot
  model: claude-sonnet-4.6
  max-turns: 20
```

| エンジン | `id` | 必要シークレット |
|---------|------|-----------------|
| Copilot（このリポジトリの既定） | `copilot` | `COPILOT_GITHUB_TOKEN`（または `copilot-requests: write`） |
| Claude | `claude` | `ANTHROPIC_API_KEY` |
| Codex | `codex` | `OPENAI_API_KEY` |
| Gemini | `gemini` | `GEMINI_API_KEY` |

> 💡 **モデルを実行時に切り替える**には、`model: ${{ github.event.inputs.model }}` と式を埋め込みます。採用モデル（Copilot エンジン）: `claude-sonnet-4.6`（バランス・既定）/ `gpt-5.4`（汎用）/ `gpt-5.3-codex`（コード調査）/ `claude-haiku-4.5`（高速・低コスト）。

## safe-outputs（安全な書き込み）

AI の出力を**検証済みの GitHub 操作**に変換します。代表例:

```yaml
safe-outputs:
  add-comment:                # Issue/PR にコメント
    max: 1
    target: "*"               # "triggering"（既定）/ "*" / 番号指定
  create-pull-request-review-comment:   # コード行へのレビューコメント
    max: 20
  submit-pull-request-review: # レビューをまとめて提出（APPROVE/REQUEST_CHANGES/COMMENT）
    max: 1
  add-labels:                 # ラベル付与（状態管理に利用可）
    allowed: [ai-review-1, ai-review-2, ai-review-3, ai-review-done]
    max: 1
  create-pull-request:        # PR を作成（README 自動更新で使用）
    title-prefix: "[ai] "
    labels: [automated]
```

### AI が safe-outputs を発行する仕組み

AI は本文の指示に従い、応答の中に **JSON オブジェクト**として出力要求を書きます。`type` フィールドで操作種別を指定します。

```json
{ "type": "add_comment", "body": "レビュー結果のコメント本文" }
{ "type": "add_labels", "labels": ["ai-review-2"] }
```

フロントマターで宣言していない safe-output は実行されません（宣言が許可リストの役割を果たします）。

## 状態の永続化パターン（レビュー回数のカウント等）

gh-aw のワークフローはステートレスに起動するため、**実行間で状態を持ち越す**には GitHub 上の永続データを使います。本リポジトリの PR レビューワークフローは次の2つを併用します:

1. **PR ラベル**（`ai-review-1` / `ai-review-2` / `ai-review-3` / `ai-review-done`）でレビュー回数を表現する
2. **過去の AI レビューコメント本文**を読み戻して、前回の指摘観点を引き継ぐ

これにより「同一観点で再レビューし、修正のたびに件数を収束させる」が実現できます。詳細は [05-同梱ワークフロー解説.md](05-同梱ワークフロー解説.md) を参照してください。

## 最小テンプレート

```markdown
---
name: My Workflow
on:
  workflow_dispatch:
    inputs:
      topic:
        description: "対象"
        type: string
        required: true
engine: claude
permissions:
  contents: read
safe-outputs:
  add-comment:
    max: 1
---

# やること

`${{ github.event.inputs.topic }}` について調べ、要約をコメントしてください。
```

書けたら必ず `gh aw compile` してから `.md` と `.lock.yml` を両方コミットします。
次は [04-CLIコマンドリファレンス.md](04-CLIコマンドリファレンス.md) を参照してください。
