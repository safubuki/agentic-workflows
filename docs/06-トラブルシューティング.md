# 06. トラブルシューティング & FAQ

## よくある問題

### Q. ワークフローが Actions に表示されない / 実行されない
- `.lock.yml` をコミットし忘れていないか確認。Actions が実行するのは `.lock.yml` です。
- `.md` 編集後に `gh aw compile` を実行したか確認。
- `.md` と `.lock.yml` の**両方**が push されているか確認。

### Q. `gh aw compile` でエラーになる
- フロントマターの YAML 構文を確認（インデント・コロンの後ろのスペース）。
- `safe-outputs` に宣言していない出力タイプを本文で使っていないか確認。
- `engine`・`on`・`permissions` のフィールド名のスペルを確認。

以下は実際によく出るメッセージごとの対処です。

### Q. compile で `not in a git repository` と出る
- `gh aw compile`（引数なし）は git リポジトリ内でのみ動きます。
- **直し方**: リポジトリ直下で `git init` してから再実行。

### Q. compile で `unauthorized expressions found`（例: `github.sha`）と出る
- 本文やフロントマターで使える `${{ ... }}` の式は**許可リスト制**で、`github.sha` などは使えません。
- **直し方**: エラーに表示される許可式に置き換える。よくある対応:
  - push のコミット SHA → `github.event.head_commit.id`
  - PR 番号 → `github.event.pull_request.number`
  - 手動入力 → `github.event.inputs.<名前>`

### Q. compile で `Missing required permissions for GitHub toolsets` と警告が出る
- `tools: github:` を使うと、その操作に必要な `permissions` が求められます（例: `issues: read`、`pull-requests: read`）。
- **直し方**: 警告に出た権限をフロントマターの `permissions` に追加して再コンパイル。

### Q. compile で `safe update mode detected unapproved changes`（新しいシークレット）と出る
- 新しいシークレット（例: `ANTHROPIC_API_KEY`）を使う設定を追加すると、安全のため**承認待ち**になります（エラーではなくレビュー要求）。
- **直し方**: 中身が正しい（流出等の不審な使い方でない）ことを確認のうえ、`gh aw compile --approve` で承認。

### Q. AI が「権限がない」「書き込めない」と言う
- 書き込みは `safe-outputs` 経由でのみ可能です。直接 push やファイル書き込みはできません。
- 必要な safe-output（`add-comment` / `create-pull-request` 等）をフロントマターで宣言しているか確認。

### Q. シークレットが見つからないエラー
- 本リポジトリは **Copilot エンジン**なので、必要なのは `COPILOT_GITHUB_TOKEN`（または `permissions: copilot-requests: write`）です。
- `gh secret set COPILOT_GITHUB_TOKEN` で登録し、`gh secret list` で確認。
- （参考）他エンジンを使う場合: Claude→`ANTHROPIC_API_KEY` / Codex→`OPENAI_API_KEY` / Gemini→`GEMINI_API_KEY`。

### Q. モデルが解決できない / 指定モデルで動かない
- `model:` の文字列が **Copilot のモデル ID 表記**と一致しているか確認（例: `claude-sonnet-4.6` / `gpt-5.4` / `gpt-5.3-codex` / `claude-haiku-4.5`）。
- 表記は環境で変わり得ます。正確な ID は GitHub の Copilot 設定や実行ログで確認し、合わせて再コンパイル。
- 詳細は [references/model-policy.md](references/model-policy.md)。

### Q. workflow_dispatch の入力が本文に反映されない
- 本文では `${{ github.event.inputs.<入力名> }}` の形式で参照します。
- 入力名（`inputs:` 直下のキー）とスペルが一致しているか確認。

### Q. PR レビューの回数カウントが想定とズレる
- 回数は PR のラベル `ai-review-1/2/3` で管理しています。手動でラベルを付け外しすると回数判定が変わります。
- やり直したい場合は、PR から `ai-review-*` ラベルをすべて外せば初回からになります。

### Q. README 自動更新の PR が作られない
- 今回の変更が README 反映不要（内部実装・テストのみ等）だと、設計上 PR を作りません。報告コメント/ログを確認。
- `paths-ignore` に該当する変更（`docs/`・`*.lock.yml`・skills）だけだと起動しません。

### Q. 見覚えのない `agentics-maintenance.yml` がある
- これは **gh-aw が自動生成するメンテナンス用ワークフロー**です（対になる `.md` はありません。正常）。
- `expires` 付きの safe-output を使うワークフローがあると生成され、期限切れの後始末などを定期実行します。手で編集しない（`DO NOT EDIT`）。
- 不要なら `.github/workflows/aw.json` に `{"maintenance": false}` を置いて再コンパイルすれば生成されなくなります（既存ファイルは手動削除）。

## デバッグ手順

```bash
# 実行履歴を見る
gh run list --workflow "PR AI Review"

# 特定実行のログを見る
gh run view <run-id> --log

# 拡張・設定を再初期化
gh aw init
```

## FAQ

**Q. `.md` だけ Actions に置けば動く？**
A. いいえ。`gh aw compile` で生成した `.lock.yml` が実行対象です。両方コミットします。

**Q. モデルを実行ごとに変えられる？**
A. はい。`workflow_dispatch` の `choice` 入力で選び、`engine.model: ${{ github.event.inputs.model }}` に渡します（PR レビューワークフローの実装例）。

**Q. 外部 DB なしで回数や前回指摘を覚えられる？**
A. はい。GitHub のラベル（回数）と過去コメント（前回指摘）を読み戻して永続状態として使います。

**Q. 安全性は？**
A. AI は既定で読み取り専用。書き込みは検証済みの `safe-outputs` のみ。`gh aw compile` がセキュリティ強化を行います。
